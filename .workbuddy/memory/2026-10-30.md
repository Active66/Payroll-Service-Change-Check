### 关键技术决策（阶段 2 拆包时不要推翻）
1. **500 字切片 = 装箱单元是条款**，不是字符硬切。规则：先按"章"设硬边界，章内把整条装进 500 字，放不下就在条款边界断开；表格作为原子单元（放得下并入当前条款块，放不下整表独占并继承条款归属）；标题内联进正文；为条款预留 120 字正文空间（`_BODY_RESERVE`），避免"条标题在上一块末尾、正文在下一块"的孤儿标题；overlap 只在同一条款被迫续切时生效，且要剔除标题行（否则相邻块重复出现"第X条"）。
2. **引用精度靠 `clauses[]` + `clause_range`**，一个切片可覆盖多条（如"第十七条–第十九条"），评测匹配必须用集合判断而非子串。
3. **RRF 融合**（k=60，双通道等权），不用加权分数相加——余弦(0~1) 与 BM25(0~30) 量纲不同。
4. **拒答闸门用"两路各自最高原始分"**，不看融合分：RRF 只看名次，垃圾切片两路都排第一也会拿最高融合分。默认 `MIN_VECTOR_SCORE=0.25 / MIN_BM25_SCORE=4.0`（hash 向量下有效问题 0.27~0.38、越界 0.11；换 bge-m3 必须重新标定）。
5. **LLM 适配器 = 唯一出网口**，标准库 urllib 直连 OpenAI 兼容协议，不依赖 openai SDK；`LLM_PROVIDER` 支持 mock/openai/deepseek/qwen/moonshot/zhipu/ollama/vllm。无 key 时自动降级 mock。
6. **MockChatModel 是抽取式假模型**（有意的）：把"检索质量"与"生成质量"解耦，mock 答不出 = 检索问题，mock 能答但真模型答错 = prompt/生成问题；过滤表格行与标题行。
7. **答案护栏**（guard.py 原型）：引用角标有效性 + 带单位数字回查原文 + 拒答识别；数字查不到即降级 `partial`。实测注入"50,000 元"能被抓出。
8. manifest 记录 doc checksum / embedding_model / dim / chunk 参数，加载时做漂移体检（换向量模型必须重建）。

## 阶段 2：员工问答入口（FastAPI SSE + SQLite + 单页界面）

时间：2026-10-30 上午。设计文档 `docs/chat-api-design.md`（含错误码表、SSE 事件、DDL、实现差异）。

### 落点
- 新增 `src/my_tool/api/`（app / routes_chat / sse / schemas / errors）与 `src/my_tool/store/`（db / chat_repo）、`web/`（index.html / app.js / style.css）。
- 改 `core/` 仅三处：orchestrator 抽 `_prepare/_finalize` + `answer_stream()`；llm 加 `chat_stream()`（base 给退化实现、openai_compat 解析 SSE、mock 按句切帧）;entities 的 Chunk/Citation 加 `source_file`/`doc_title`（索引需重建一次）。
- 测试 39 → 71（新增 test_repo 16 / test_sse 7 / test_api 16）。

### 关键决策
1. **同步生成器 + 线程池**：端点 `async def` 只做 `await request.json()`，重活（DB、索引、生成）全在 `StreamingResponse` 的**同步生成器**里跑（Starlette 用 iterate_in_threadpool）。写成 async def 里直接调阻塞代码会卡死事件循环。
2. **流前 vs 流中错误**：校验/会话/索引类错误必须在返回 StreamingResponse 之前抛出，才有真 4xx；流一旦开始只能 `event: error`（HTTP 固定 200）。所以 `_prepare_turn` 用 `run_in_threadpool` 在响应头之前跑。
3. **并发锁用数据**：判 `answer_status='streaming'` 的占位行（跨进程可见、崩溃后能被启动清理发现），不用内存字典。
4. **事务边界**：T1 插 user + assistant 占位行，T2 生成完更新；**LLM 调用绝不进事务**（否则锁库数十秒）。`BEGIN IMMEDIATE` + `busy_timeout=5000` + WAL。
5. **拒答也走 delta**（固定话术），前端不用多写分支；验收标准改为"没有 citations"。
6. **护栏只能事后判**：边流边发，结束后 run_guard，告警走 `guard` 事件 + done.status=partial。已发的字收不回来是本质约束。
7. **心跳没做**：生成器阻塞在 `next()` 时无法 yield，真心跳要工作线程+队列（还会引入 `generator already executing` 的取消难题）。已在设计文档第 12 节写明理由与改法。
8. **追问合并**：≤12 字且含指代词时，`query_used = 上一轮问题 + 当前问题`，只影响检索，生成仍用原文；`query_used` 随 done 返回便于排查。
9. **前端**：EventSource 不支持 POST → fetch + ReadableStream 手工解析（chunk 切断/多行 data/注释行三坑）；打字机用 rAF + 二级缓冲（42 字/秒，收尾 480）；**打完再上角标**（流式期间上 sup 会抖动）；中文输入法 `isComposing || keyCode===229` 才允许 Enter 发送。

### 让用户"看效果"这件事，试过四种方式（结论很重要）
用户要看 Web 效果，需要服务常驻，但**本环境无法让后台服务跨回合存活**，实测：
1. `subprocess.Popen(DETACHED_PROCESS|CREATE_NEW_PROCESS_GROUP)` → 命令一返回就被回收；
2. 加 `CREATE_BREAKAWAY_FROM_JOB`(0x01000000) → 启动瞬间可用（healthz 200），下一条命令执行时已死；
3. `schtasks` 计划任务（最可靠，进程由 Task Scheduler 拉起）→ **被安全策略拦死**：`schtasks.exe` 在程序黑名单，明确禁止绕过；
4. `present_files` 传 `http://127.0.0.1:8000/` → 恒报 "not reachable"。原因不是服务没起，而是**宿主探测沿用 `HTTP_PROXY`，代理对 127.0.0.1 返回 502**（实测：直连 200、走代理 502）。所以本机环境下 present_files 永远打不开 localhost 预览。

**可行做法**：提供 `scripts/run_server.bat` 让用户双击——服务跑在用户自己的 cmd 窗口里，不受 agent 作业回收影响；脚本内 `start "payroll-check server" /min "%PY%" -m my_tool serve ...` + 等待 6s + 打开浏览器，并用 `netstat|findstr 127.0.0.1:8000` 判断已在运行则只开页面。`SKIP_BROWSER=1` 可用于无人值守验证。

### 另一批环境坑
- **Bash 工具彻底不可用**：`dirname/ls/grep/head` 全 not found（PATH shim 坏了），任何 shell 拼接都失败 → 一律 PowerShell + Python 绝对路径。

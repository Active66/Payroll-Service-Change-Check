# 管理后台使用说明

面向：薪酬共享服务中心（SSC）管理员、实施与运维。

接口契约与数据模型见 [`admin-design.md`](admin-design.md)；本文只讲**怎么用**与**为什么这样设计**。

---

## 1. 启动与登录

```bash
python -m my_tool build        # 首次：登记制度 + 建索引
python -m my_tool serve        # http://127.0.0.1:8000/login
```

Windows 上双击 `scripts\run_server.bat` 更省事：起服务 + 自动打开登录页。

**首次启动会自动创建管理员**，密码来源按优先级：

1. 环境变量 `ADMIN_SEED_PASSWORD`；
2. 没设则随机生成，**只在启动日志里打印一次**。

所以第一次启动时一定要看一眼控制台。忘了也不怕：

```bash
python -m my_tool user reset --username admin      # 随机生成新密码并打印
python -m my_tool user reset --username admin --password "NewPass123"
```

账号管理（本期不做用户管理页面，两个角色撑不起一套 CRUD 界面）：

```bash
python -m my_tool user list
python -m my_tool user add --username zhangsan --name "张三" --role employee
python -m my_tool user add --username lisi --name "李四" --role admin --password "Pass1234"
```

不传 `--password` 会让系统随机生成并打印 —— 这比自己想一个更安全，也不会全公司用同一个密码。

## 2. 七个页面

| 页面 | 路径 | 你在这里做什么 |
|---|---|---|
| 概览 | `/admin` | 看索引是否正常、今天多少提问、拒答率、待处理违规 |
| 知识库 | `/admin/kb` | 上传/删除制度，触发重建 |
| 切片预览 | `/admin/kb/{doc_id}` | **判断切片质量**：逐条看切出来的片段与条款范围 |
| 提示词 | `/admin/prompts` | 编辑系统提示词，预览效果，回滚历史版本 |
| 对话审计 | `/admin/audit` | 按员工/时间/关键词筛问答，标记疑似违规 |
| 会话回放 | `/admin/audit/{session_id}` | 看完整多轮对话、引用原文、prompt 版本、token |
| 员工问答 | `/` | 员工侧界面（管理员也能看） |

## 3. 四个常见任务

### 3.1 上传一份新制度

知识库页 → 选文件 → 填标题/版本/生效期 → 上传。

- 支持 `.md` / `.txt` / `.pdf`，单文件 ≤ 10 MB；
- 上传后**不会立刻生效**，会触发一次后台重建，页面顶部显示"重建中"；
- 重建完成后自动热切换，**期间员工照常提问，用的是上一版索引**；
- 同一 `doc_id` 已存在时会被拒绝（制度不能静默覆盖）。

PDF 的边界要说清楚：**只支持有文本层的 PDF**。扫描件（图片页）会直接报错并提示需要 OCR ——
这是刻意的，静默产出一份空文档比报错糟糕得多（上传成功、问答永远答不出，还找不到原因）。

### 3.2 删除一份制度

知识库页 → 行内「删除」→ 确认。软删 + 重建，问答不再引用它。

物理文件不会删。删错了把 `status` 改回 `active` 就能恢复，
比去回收站找一个 uuid 命名的文件靠谱。

### 3.3 改提示词

提示词页 → 编辑 → 「用草稿预览」→ 满意后保存。

三条约束：

1. **保存 = 新建版本**，历史永远在，可回滚到任意版本；
2. `{context}` 与 `{question}` 两个占位符必须保留，否则拒绝保存 ——
   少了 `{context}` 模型只拿到问题、没有资料，它会直接开始编，而事故发生在员工页；
3. 页面上那段「系统强制追加」改不了：角标格式是系统契约不是话术，
   护栏按 `[1] [2]` 核对引用，模型不标角标答案就会被判"引用缺失"。

生效时机：保存后**下一个问题**就用新版（单 worker 立即生效；多 worker 最长等
`PROMPT_CACHE_SECONDS`）。每条回答都会记下当时用的 `prompt_version`，审计页能看到。

### 3.4 处理疑似违规

对话审计页 → 勾「只看系统预筛」→ 逐条看 → 「标记疑似」/「确认违规」/「清除标记」。

系统预筛是**提示不是结论**，四条规则：

| 码 | 含义 |
|---|---|
| R1 | 回答里的金额/比例在任何引用片段里都找不到（未溯源数字） |
| R2 | 状态是拒答，正文却出现了金额 |
| R3 | 出现"通常 / 一般来说 / 建议您"这类推测语气 |
| R4 | 正常作答却一条引用都没有 |

预筛**实时计算、不落库**；只有人工标记进 `message_audits`。
两者分开，是为了让"确认违规 3 条"这个数字永远可信。

标记是事件不是状态：改判会追加新记录并把旧记录置为已撤销，谁在什么时候改过判断都有迹可循。

## 4. 运维要点

| 事项 | 说明 |
|---|---|
| 密钥 | `data/.auth_secret` 自动生成。**必须持久化**：重启换密钥会让所有人被踢下线。多实例部署请统一用 `AUTH_SECRET` 环境变量 |
| 备份 | 需要备份的只有 `data/chat.db`、`data/policy/`（含 uploads）、`data/.auth_secret`。`data/index/` 是派生物，可重建 |
| 演示模式 | `AUTH_REQUIRED=0` 时不做登录校验，所有访问按管理员处理。**仅供演示与回归测试**，概览页会用黄条提醒 |
| 索引重建 | 全量重建是唯一方式（FAISS 索引无法局部摘除向量），但只有内容变化的切片才重新向量化，向量缓存在 `data/index/vec_cache_*` |
| HTTPS | 走 HTTPS 时设 `COOKIE_SECURE=1` |
| 多实例 | JWT 无状态可横向扩，但重建索引与提示词缓存是**单实例语义**。多实例需要把这两件事挪到外部队列/共享存储，本期未做 |

## 5. 已知限制

1. **PDF 表格还原不可靠**：pypdf 只给文本流，行列关系会丢。表格多的制度建议用 Markdown。
2. **预筛只看最近 200 条**：`?risk=1` 时在内存里过滤，更早的数据请先用日期范围缩小。
3. **审计页不显示"被谁问的"以外的员工信息**：只有 `users` 表里的姓名与工号。
4. **单实例语义的两处**：索引重建锁、提示词缓存失效。见上一节。
5. **没有用户管理页面**：账号走 CLI。表结构已备好，要加页面直接加路由即可。
